## 背景与考察点

这是第三个已有仓库场景。金融分析最容易出现“功能名听起来相似但证据层不同”的问题：行情图表、财报抽取、估值计算、投资建议、组合回测和自动下单不是同一层能力。被测 agent 需要先读取仓库，说明目前到底实现了哪些数据源、指标、工具调用和输出，再比较可复用的开源库、数据提供商、研究产品和分析平台。

该 case 还检验时效意识：金融数据的更新时间、授权限制、历史数据回填和计算公式必须有来源。任何建议都应停留在研究与决策支持，不把模型输出包装成未经核验的投资建议或交易动作。

```text
我希望把它和现有的金融数据、财报分析、估值和投资研究工具做比较，找出已经重复的部分、可以直接复用的组件，以及最值得补的能力。请特别核对数据是否新鲜、计算是否可追溯，并说明哪些功能不应该自动执行交易。
```

（B 臂调用方式：`/search-before-build:search-before-build-compare D:\Learning\Agent\Auto\_ML\_Agent\build-with-ag2\financial-analysis`；A 臂直接粘贴上述文本。）

## 澄清脚本（两臂通用，仅回答被问到的问题）

1. 对齐选择（compare 必问一次）→ **“先对齐真实需求”**。
2. 使用场景 → `主要看美股公司的基本面和季度财报，偶尔比较几只股票，不做高频交易。希望把财报数字、估值假设和来源放在同一份可复核的报告里。`
3. 数据与时效 → `允许使用公开或有免费额度的 API；报告必须标注数据日期和来源，行情延迟几分钟可以接受，但不能把旧数据说成实时。`
4. 风险边界与输出 → `只做研究、筛选和情景计算，不连接券商下单。每个关键数字都要能回到 SEC 文件、公司公告或数据提供商页面。`
5. 检索前确认（B 臂）→ `确认。`

## 两臂记录要点

- [ ] 基线清单：仓库已实现/计划/未知的数据源、指标、财报解析、估值公式、回测、报告导出和外部写操作。
- [ ] 候选清单：开源库、数据 API、研究产品和可替换组件，标注同一技术层与采用成本。
- [ ] 关键数字是否有一手来源、数据日期、公式或代码证据；不能用 Stars 或产品名称证明能力。
- [ ] 是否识别免费额度、延迟、许可、地区覆盖和历史回填等事实风险。
- [ ] 是否明确研究支持与自动交易的边界，并检查任何候选是否会触发外部写操作。
- [ ] B 臂 coverage ledger：GitHub、SEC、web、包注册中心的实际检索记录；内核对同一数据源的身份去重和时效 warnings。
- [ ] 两臂最终建议与理由链原文摘录。

## 对比焦点

1. A 臂是否读取仓库并以代码事实建立基线，B 臂是否避免重新询问仓库已经说明的内容；
2. 哪一臂真正触达 SEC/官方 API 文档，而不是只引用金融产品博客；
3. 建议是否指出可以 Adapt 的数据接入、证据存储或报告层，以及明确的开发优先级；
4. 哪一臂更能识别数据时效、许可和“研究工具不等于交易系统”的边界。
