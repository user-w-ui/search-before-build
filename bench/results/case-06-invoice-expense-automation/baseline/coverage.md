## 与请求逐项对应

1. **输入分散**：Paperless/Docspell 可从邮件或目录收集；InvoiceFlowAI 偏 QQ/163；invoice-pay-record-manager 偏微信目录；发票盒子覆盖最多但为云端；没有候选同时公开证明 Outlook、微信/支付宝和手机照片都能在本地自动收集。
2. **字段识别**：中国 VAT OCR 和 FP 报销系统覆盖发票代码/号码、日期、购销方、金额/税额/明细；手机纸票的清晰度和票种仍需用真实样本验收。Microsoft AI Builder 支持简体中文和置信度，但处理在云端。
3. **重复与抬头**：文件 hash 能捕获字节相同副本；发票代码+号码（以及必要时日期、金额）能补上文件变体；抬头需要配置预期购买方名称/税号后做字段比较。现成文档很少把这两项同时做成个人默认工作流。
4. **月度 Excel**：FP、InvoiceFlowAI、票亮和 invoice-ledger-skill 明确支持，Power Automate/Expensify 也能导出；输出时应把发票号/代码作为文本，防止 Excel 丢失前导零。
5. **私有数据**：Paperless、Docspell、FP、票亮和本地台账工具能作为默认本地路径；AI Builder、Expensify、发票盒子、云 OCR API 与该要求冲突；本地工具若启用视觉 API 也会产生外传例外。
6. **发信前确认**：应由自建应用把“确认字段/生成报销包”和“发送邮件”拆成两个状态与按钮；候选的审批或人工复核不能自动视为满足该硬约束。

## 证据边界

网页没有提供针对用户本人样本的准确率、照片质量阈值、真实抬头错误率或重复票召回率。任何上线判断都需要准备至少一批带文本层 PDF、一批微信/支付宝导出 PDF 和一批手机拍照纸票，逐字段核对并记录低置信度/人工修改率。
