# Candidates and current alternatives

The links below were directly opened during this run. Characterizations are based on the linked project documentation as observed on 2026-09-03; small GitHub projects are identified as examples or prototypes rather than assumed to be mature competitors.

| Candidate | Link | What it covers | Gap against the request |
| --- | --- | --- | --- |
| Tabula | [tabula.technology](https://tabula.technology/) | MIT, Linux/Windows/macOS, local browser UI, user-drawn region, Preview & Export, CSV/Excel. | Explicitly text-PDF only; latest site release is 1.2.1 from June 4, 2018. The GitHub README says the end-user app is unlikely to receive near-term updates; local mode still makes version-check and statistics calls unless disabled. |
| Tabula Java core | [tabulapdf/tabula](https://github.com/tabulapdf/tabula) | Reusable Java extraction heuristics and CLI; upstream explicitly invites incorporation into other projects. | Java/runtime integration and old UI; no OCR or scanned table path in the documented baseline. |
| Excalibur | [excalibur-py.readthedocs.io](https://excalibur-py.readthedocs.io/en/master/) | Local Python web UI over Camelot; manual/automatic table selection, data view, CSV/Excel/JSON/HTML download, reusable extraction settings, Linux executable claim. | Release 0.4.3 documentation says text-PDF only and requires Ghostscript; it is a local web UI rather than a polished Debian desktop workflow. |
| Camelot | [camelot-dev/camelot](https://github.com/camelot-dev/camelot) | MIT Python library; lattice/stream/network/hybrid parsers, pandas tables, CSV/Excel export, per-table accuracy/whitespace/confidence metrics, multi-page stitching. Current repository documents optional Table Transformer plus OCR for scans. | No end-user review UI. Scanned support is opt-in (`[ml,ocr]`) and brings PyTorch/model/OCR packaging; stable docs still state that the base library is text-PDF only. |
| pdfplumber | [jsvine/pdfplumber README](https://github.com/jsvine/pdfplumber/blob/stable/README.md) | MIT Python extraction with cell/row/column/bounding-box objects, configurable table strategies, and debug table finder. | It is a library, not a desktop app; the documented table path assumes PDF geometry/text and does not supply OCR or spreadsheet review UX. |
| OCRmyPDF | [OCRmyPDF cookbook](https://ocrmypdf.readthedocs.io/en/latest/cookbook.html) and [Debian package](https://packages.debian.org/bookworm/ocrmypdf) | MPL-2.0 local OCR layer, Tesseract languages, sidecar text, validation, parallel pages; available as a Debian package. | Produces searchable PDF/text, not detected tables or XLSX/CSV. External system dependencies include Ghostscript and Tesseract; language packs and packaging need to be managed. |
| Docling | [docling.ai](https://docling.ai/) and [table export example](https://docling-project.github.io/docling/_generated/examples/export_tables/) | MIT, local/offline after model artifacts are present; PDF/image OCR, layout, table structure, provenance; `table.export_to_dataframe()` can be written to CSV/HTML and runs on CPU or accelerator backends. | No documented desktop preview/editor or direct XLSX export in the cited example. Model artifacts and model-path/offline setup add download, disk, memory, and packaging work. |
| Microsoft Table Transformer | [microsoft/table-transformer](https://github.com/microsoft/table-transformer/blob/main/README.md?plain=1) | Open-source research building block for table detection/structure from PDF images; official inference can produce HTML/CSV. | It recognizes structure but requires OCR or native text separately to populate cell text; it is not a desktop product and needs model/runtime integration. |
| openstan | [openstan.org](https://openstan.org/) | LGPL-3 Debian `.deb`, local/offline bank-statement workflow, side-by-side review/debug, Excel/CSV/JSON export, extensible bank configs, coverage-gap checks. | Focused on supported UK banks and financial transactions rather than arbitrary brokerage/corporate tables. It proves that domain-specific local review can be useful. |
| MoneyLens | [futuraeleven/moneylens](https://github.com/futuraeleven/moneylens) | MIT local-first ING statement archive; packaged Linux AppImage, local UI, PDF import, dry-run, searchable SQLite and transaction data. | Bank-specific (currently ING), clone-and-run architecture, and a finance dashboard rather than arbitrary table extraction with a source-cell preview. |
| PDFcsv | [stexz01/pdfcsv](https://github.com/stexz01/pdfcsv) | MIT Linux/macOS/Windows CLI; coordinate/gap-based column detection, interactive live preview, bank debit/credit handling, CSV/XLSX/JSON/TSV/Markdown, encrypted PDF messages. | README documents text-coordinate extraction and explicitly lists GUI as future contribution; no scanned/OCR workflow is documented. |
| PDF Workbench | [Iamakashgaur/pdf-workbench](https://github.com/Iamakashgaur/pdf-workbench) | Recent implementation example with native/scanned/mixed routing, pdfplumber/Camelot/Tabula cascade, Tesseract, preview, XLSX/CSV, row/amount reconciliation, and unparsed-row reporting. | The generic path is bounded by a supplier-specific parser; scans require Tesseract, optional engines need system dependencies, and the UI is an optional Streamlit app rather than a native Debian utility. |
| Anchor | [anchor.aidenpaleczny.com](https://anchor.aidenpaleczny.com/) | Closest current product match: local OCR + vision model, Excel/CSV export, source-region highlight per cell, green/yellow/red confidence, no uploads/telemetry after setup. | Published support is Windows 10/11 and Apple Silicon macOS only; it is beta, Elastic License 2.0, needs about 3.5 GB of models and 8 GB RAM, and needs internet for first-run setup. Debian is the clear opening. |
| excelfrompdf | [Bhanusrimattey/excelfrompdf](https://github.com/Bhanusrimattey/excelfrompdf) | Small code example claiming native/scanned routing, OCR, edge detection, orientation correction, and XLSX output. | No desktop preview; requires Tesseract and optionally Google Cloud Vision, and is under BUSL 1.1 with non-commercial restrictions. Treat as a prototype to inspect, not a dependency to embed without a license decision. |
| PDF Arranger | [pdfarranger/pdfarranger](https://github.com/pdfarranger/pdfarranger) | GPL-3 Python/GTK Linux desktop, maintained page thumbnails/reordering/cropping/search, pikepdf frontend; a plausible host for a native action. | Documented scope is page manipulation, with no table extraction/OCR/export subsystem. A plugin or worker boundary would be needed. |
| PDFsam Basic | [pdfsam.org/pdfsam-basic](https://pdfsam.org/pdfsam-basic/) | AGPL desktop app for Linux/macOS/Windows; local/offline split, merge, mix, rotate and page extraction. | Documented Basic edition has no table extraction or spreadsheet export; adding this would be a large new module. |

## Evidence notes

- Tabula and Excalibur validate the value of selecting a region, previewing the result, and adjusting extraction before export.
- Camelot's current repository shows that a local pipeline can combine deterministic parsers, OCR, and a table model, but the model supplies structure while OCR supplies text. That separation is useful for preserving source text and confidence.
- OCRmyPDF and Tesseract make Debian-local OCR practical, but an OCR layer is only an input to table reconstruction.
- Docling narrows the implementation gap for mixed/scanned documents, but the application still needs typed export, editing, provenance, and packaging.
- openstan, MoneyLens, PDFcsv, PDF Workbench, and Anchor show that privacy-first finance/document extraction is an active problem with several narrow solutions. They also show that domain templates, review, and validation are the product surface.
