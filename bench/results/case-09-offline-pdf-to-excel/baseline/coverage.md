# Requirement coverage

| User requirement | Existing evidence | Best current coverage | Remaining gap / product implication |
| --- | --- | --- | --- |
| Debian/Linux desktop | PDF Arranger is Python/GTK with Debian dependencies; PDFsam is Linux desktop; Tabula has a Linux JAR/browser path; openstan publishes Debian packages; MoneyLens publishes a Linux AppImage. | High for host utilities and several narrow tools. | Anchor, the closest full workflow, publishes Windows/macOS support only. A Debian-native package and installer experience can still differentiate. |
| Fully offline and private | PDFsam says files stay local and no internet is needed; Tabula says local processing but documents update/stat calls unless disabled; Docling runs offline after model artifacts are available; openstan and MoneyLens describe local operation. | High for deterministic pipelines; medium for model pipelines until artifacts are bundled. | Ship with network disabled by default, prebundle or explicitly stage model files, and expose a visible no-egress check. Avoid silent update checks for sensitive workflows. |
| Text-based PDF tables | Tabula, Camelot, pdfplumber, Excalibur, PDFcsv all use selectable text/coordinates and/or table geometry. | High. | General layouts still need a region selector, per-document settings, and failure reporting. |
| Scanned pages | OCRmyPDF/Tesseract supply local OCR; current Camelot repository documents optional `[ml,ocr]`; Docling supports OCR and table structure; Table Transformer supplies image structure with separate OCR; PDF Workbench and Anchor show end-to-end examples. | Medium at the engine level. | OCR digit/sign/date mistakes and table reconstruction remain the hard path. Keep OCR word boxes/confidence and require review of flagged cells. |
| Preview detected table before export | Tabula and Excalibur explicitly preview; PDFcsv has interactive live preview; openstan has side-by-side review; Anchor highlights source regions. | High in separate tools. | No single maintained Debian app combines preview with both text and scanned extraction. Make preview a required gate before export. |
| Clean Excel/CSV | Tabula, Excalibur, Camelot, openstan, PDFcsv, PDF Workbench, Anchor document CSV/XLSX export; Docling example exports tables through pandas to CSV. | High for output formats. | Clean values require typed cells, stable headers, multi-page stitching, and preservation of raw OCR text. CSV alone cannot carry cell types or provenance. |
| Preserve numbers and dates for Calc | LibreOffice documentation warns that CSV dates and decimal numbers can be interpreted using the current locale; CSV export loses formulas/formatting. XLSX supports typed cells and explicit number/date formats. | Medium. | Ask for locale/decimal conventions, keep raw source text beside normalized typed values, and never silently coerce ambiguous dates or signs. |
| Manual checking | Camelot has table metrics; openstan shows debug output and original PDFs side by side; Anchor gives per-cell confidence and source highlight; TabSniper describes balance checks and post-processing. | Medium to high in narrow tools. | Make provenance, confidence, and low-confidence correction first-class data, not a last-minute report. Add row-count, total, and running-balance checks where the document supports them. |
| Corporate reports and brokerage notes | Docling/Table Transformer target general documents; Camelot/pdfplumber target generic tables; FinTabNet/Table Transformer cover financial layouts. | Medium. | Bank-specific parsers are not enough. Start with a small set of document families and allow saved region/schema templates. |
| Integration into an existing open-source PDF utility | Tabula says its Java core can be incorporated; PDF Arranger is a maintained GTK/Python Linux host; PDFsam is a maintained local Java host. | Feasible. | PDF Arranger/PDFsam do not expose table extraction in their documented scope. Prefer a separate local worker/library with an optional host action so OCR/ML dependencies do not bloat or destabilize the base PDF utility. |

## Technical difficulty signal

The 2024 TabSniper paper is a useful warning: bank layouts vary, statements can be long multi-page tables with dense multi-line rows, and scanned versus electronic PDFs behave differently. It uses separate table detection/categorization, OCR coordinates, table structure recognition, and post-processing; it also reports failures on tilted scanned documents. This supports a scoped, review-first product and argues against promising universal accuracy.
